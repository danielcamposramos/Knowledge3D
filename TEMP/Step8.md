1 Introduction
--------------

While powerful, Large Language models (LLMs) can struggle on hard question-answer problems. Given that they generate their answer auto-regressively, there is a high risk of error since a single incorrect token can render an answer invalid. To improve their reliability, LLMs rely on Chain-of-thoughts (CoT) (Wei et al., [2022](https://arxiv.org/html/2510.04871v1#bib.bib35)) and Test-Time Compute (TTC) (Snell et al., [2024](https://arxiv.org/html/2510.04871v1#bib.bib29)). CoTs seek to emulate human reasoning by having the LLM to sample step-by-step reasoning traces prior to giving their answer. Doing so can improve accuracy, but CoT is expensive, requires high-quality reasoning data (which may not be available), and can be brittle since the generated reasoning may be wrong. To further improve reliability, test-time compute can be used by reporting the most common answer out of K K or the highest-reward answer (Snell et al., [2024](https://arxiv.org/html/2510.04871v1#bib.bib29)).

![Image 1: Refer to caption](https://arxiv.org/html/2510.04871v1/TRM-Page-3.drawio.png)

Figure 1: Tiny Recursion Model (TRM) recursively improves its predicted answer y y with a tiny network. It starts with the embedded input question x x and initial embedded answer y y, and latent z z. For up to N s​u​p=16 N_{sup}=16 improvements steps, it tries to improve its answer y y. It does so by i) recursively updating n n times its latent z z given the question x x, current answer y y, and current latent z z (recursive reasoning), and then ii) updating its answer y y given the current answer y y and current latent z z. This recursive process allows the model to progressively improve its answer (potentially addressing any errors from its previous answer) in an extremely parameter-efficient manner while minimizing overfitting.

However, this may not be enough. LLMs with CoT and TTC are not enough to beat every problem. While LLMs have made significant progress on ARC-AGI (Chollet, [2019](https://arxiv.org/html/2510.04871v1#bib.bib6)) since 2019, human-level accuracy still has not been reached (6 years later, as of writing of this paper). Furthermore, LLMs struggle on the newer ARC-AGI-2 (e.g., Gemini 2.5 Pro only obtains 4.9% test accuracy with a high amount of TTC) (Chollet et al., [2025](https://arxiv.org/html/2510.04871v1#bib.bib7); ARC Prize Foundation, [2025b](https://arxiv.org/html/2510.04871v1#bib.bib2)).

An alternative direction has recently been proposed by Wang et al. ([2025](https://arxiv.org/html/2510.04871v1#bib.bib34)). They propose a new way forward through their novel Hierarchical Reasoning Model (HRM), which obtains high accuracy on puzzle tasks where LLMs struggle to make a dent (e.g., Sudoku solving, Maze pathfinding, and ARC-AGI). HRM is a supervised learning model with two main novelties: 1) _recursive hierarchical reasoning_, and 2) _deep supervision_.

Recursive hierarchical reasoning consists of recursing multiple times through two small networks (f L f_{L} at high frequency and f H f_{H} at low frequency) to predict the answer. Each network generates a different latent feature: f L f_{L} outputs z H z_{H} and f H f_{H} outputs z L z_{L}. Both features (z L,z H z_{L},z_{H}) are used as input to the two networks. The authors provide some biological arguments in favor of recursing at different hierarchies based on the different temporal frequencies at which the brains operate and hierarchical processing of sensory inputs.

Deep supervision consists of improving the answer through multiple supervision steps while carrying the two latent features as initialization for the improvement steps (after detaching them from the computational graph so that their gradients do not propagate). This provide residual connections, which emulates very deep neural networks that are too memory expensive to apply in one forward pass.

An independent analysis on the ARC-AGI benchmark showed that deep supervision seems to be the primary driver of the performance gains (ARC Prize Foundation, [2025a](https://arxiv.org/html/2510.04871v1#bib.bib1)). Using _deep supervision_ doubled accuracy over single-step supervision (going from 19%19\% to 39%39\% accuracy), while _recursive hierarchical reasoning_ only slightly improved accuracy over a regular model with a single forward pass (going from 35.7%35.7\% to 39.0%39.0\% accuracy). This suggests that reasoning across different supervision steps is worth it, but the recursion done in each supervision step is not particularly important.

In this work, we show that the benefit from _recursive reasoning_ can be massively improved, making it much more than incremental. We propose Tiny Recursive Model (TRM), an improved and simplified approach using a much smaller tiny network with only 2 layers that achieves significantly higher generalization than HRM on a variety of problems. In doing so, we improve the state-of-the-art test accuracy on Sudoku-Extreme from 55% to 87%, Maze-Hard from 75% to 85%, ARC-AGI-1 from 40% to 45%, and ARC-AGI-2 from 5% to 8%.

Once the input is embedded, the shape becomes [B,L,D][B,L,D] where D D is the embedding size. Each network is a 4-layer Transformers architecture (Vaswani et al., [2017](https://arxiv.org/html/2510.04871v1#bib.bib33)), with RMSNorm (Zhang & Sennrich, [2019](https://arxiv.org/html/2510.04871v1#bib.bib38)), no bias (Chowdhery et al., [2023](https://arxiv.org/html/2510.04871v1#bib.bib8)), rotary embeddings (Su et al., [2024](https://arxiv.org/html/2510.04871v1#bib.bib31)), and SwiGLU activation function (Hendrycks & Gimpel, [2016](https://arxiv.org/html/2510.04871v1#bib.bib13); Shazeer, [2020](https://arxiv.org/html/2510.04871v1#bib.bib27)).

### 2.3 Fixed-point recursion with 1-step gradient approximation

Assuming that (z L z_{L}, z H z_{H}) reaches a fixed-point (z L∗z_{L}^{*}, z H∗z_{H}^{*}) through recursing from both f L f_{L} and f H f_{H},

z L∗\displaystyle z_{L}^{*}≈f L​(z L∗+z H+x)\displaystyle\approx f_{L}\left(z_{L}^{*}+z_{H}+x\right)
z H∗\displaystyle z_{H}^{*}≈f H​(z L+z H∗),\displaystyle\approx f_{H}\left(z_{L}+z_{H}^{*}\right),

the Implicit Function Theorem (Krantz & Parks, [2002](https://arxiv.org/html/2510.04871v1#bib.bib17)) with the 1-step gradient approximation (Bai et al., [2019](https://arxiv.org/html/2510.04871v1#bib.bib3)) is used to approximate the gradient by back-propagating only the last f L f_{L} and f H f_{H} steps. This theorem is used to justify only tracking the gradients of the last two steps (out of 6), which greatly reduces memory demands.

### 2.4 Deep supervision

To improve effective depth, deep supervision is used. This consists of reusing the previous latent features (z H z_{H} and z L z_{L}) as initialization for the next forward pass. This allows the model to reason over many iterations and improve its latent features (z L z_{L} and z H z_{H}) until it (hopefully) converges to the correct solution. At most N s​u​p=16 N_{sup}=16 supervision steps are used.

### 2.5 Adaptive computational time (ACT)

With deep supervision, each mini-batch of data samples must be used for N s​u​p=16 N_{sup}=16 supervision steps before moving to the next mini-batch. This is expensive, and there is a balance to be reached between optimizing a few data examples for many supervision steps versus optimizing many data examples with less supervision steps. To reach a better balance, a halting mechanism is incorporated to determine whether the model should terminate early. It is learned through a Q-learning objective that requires passing the z H z_{H} through an additional head and running an additional forward pass (to determine if halting now rather than later would have been preferable). They call this method Adaptive computational time (ACT). It is only used during training, while the full N s​u​p=16 N_{sup}=16 supervision steps are done at test time to maximize downstream performance. ACT greatly diminishes the time spent per example (on average spending less than 2 steps on the Sudoku-Extreme dataset rather than the full N s​u​p=16 N_{sup}=16 steps), allowing more coverage of the dataset given a fixed number of training iterations.

### 2.6 Deep supervision and 1-step gradient approximations replaces BPTT

Deep supervision and the 1-step gradient approximation provide a more biologically plausible and less computationally-expansive alternative to Backpropagation Through Time (BPTT) (Werbos, [1974](https://arxiv.org/html/2510.04871v1#bib.bib36); Rumelhart et al., [1985](https://arxiv.org/html/2510.04871v1#bib.bib26); LeCun, [1985](https://arxiv.org/html/2510.04871v1#bib.bib18)) for solving the temporal credit assignment (TCA) (Rumelhart et al., [1985](https://arxiv.org/html/2510.04871v1#bib.bib26); Werbos, [1988](https://arxiv.org/html/2510.04871v1#bib.bib37); Elman, [1990](https://arxiv.org/html/2510.04871v1#bib.bib10)) problem (Lillicrap & Santoro, [2019](https://arxiv.org/html/2510.04871v1#bib.bib20)). The implication is that HRM can learn what would normally require an extremely large network without having to back-propagate through its entire depth. Given the hyperparameters used by Jang et al. ### 2.7 Summary of HRM

HRM leverages recursion from two networks at different frequencies (high frequency versus low frequency) and deep supervision to learn to improve its answer over multiple supervision steps (with ACT to reduce time spent per data example). This enables the model to imitate extremely large depth without requiring backpropagation through all layers. This approach obtains significantly higher performance on hard question-answer tasks that regular supervised models struggle with. However, this method is quite complicated, relying a bit too heavily on uncertain biological arguments and fixed-point theorems that are not guaranteed to be applicable. In the next section, we discuss those issues and potential targets for improvements in HRM.

3 Target for improvements in Hierarchical Reasoning Models
----------------------------------------------------------

In this section, we identify key targets for improvements in HRM, which will be addressed by our proposed method, Tiny Recursion Models (TRMs).

### 3.1 Implicit Function Theorem (IFT) with 1-step gradient approximation

HRM only back-propagates through the last 2 of the 6 recursions. The authors justify this by leveraging the Implicit Function Theorem (IFT) and one-step approximation, which states that when a recurrent function converges to a fixed point, backpropagation can be applied in a single step at that equilibrium point.

There are concerns about applying this theorem to HRM. Most importantly, there is no guarantee that a fixed-point is reached. Deep equilibrium models normally do fixed-point iteration to solve for the fixed point z∗=f​(z∗)z^{*}=f(z^{*})(Bai et al., [2019](https://arxiv.org/html/2510.04871v1#bib.bib3)). However, in the case of HRM, it is not iterating to the fixed-point but simply doing forward passes of f L f_{L} and f H f_{H}. To make matters worse, HRM is only doing 4 recursions before stopping to apply the one-step approximation. After its first loop of two f L f_{L} and 1 f H f_{H} evaluations, it only apply a single f L f_{L} evaluation before assuming that a fixed-point is reached for both z L z_{L} and z H z_{H} (z L∗=f L​(z L∗+z H+x)z_{L}^{*}=f_{L}(z_{L}^{*}+z_{H}+x) and z H∗=f H​(z L∗+z H∗)z_{H}^{*}=f_{H}(z_{L}^{*}+z_{H}^{*})). Then, the one-step gradient approximation is applied to both latent variables in succession.

The authors justify that a fixed-point is reached by depicting an example with n=7 n=7 and T=7 T=7 where the forward residuals is reduced over time (Figure 3 in Wang et al. ([2025](https://arxiv.org/html/2510.04871v1#bib.bib34))). Even in this setting, which is different from the much smaller n=2 n=2 and T=2 T=2 used in every experiment of their paper, we observe the following:

1.   1.the residual for z H z_{H} is clearly well above 0 at every step 
2.   2.the residual for z L z_{L} only becomes closer to 0 after many cycles, but it remains significantly above 0 
3.   3.z L z_{L} is very far from converged after one f L f_{L} evaluation at T T cycles, which is when the fixed-point is assumed to be reached and the 1-step gradient approximation is used 

Thus, while the application of the IFT theorem and 1-step gradient approximation to HRM has some basis since the residuals do generally reduce over time, a fixed point is unlikely to be reached when the theorem is actually applied.

In the next section, we show that we can bypass the need for the IFT theorem and 1-step gradient approximation, thus bypassing the issue entirely.

### 3.2 Twice the forward passes with Adaptive computational time (ACT)

HRM uses Adaptive computational time (ACT) during training to optimize the time spent of each data sample. Without ACT, N s​u​p=16 N_{sup}=16 supervision steps would be spent on the same data sample, which is highly inefficient. They implement ACT through an additional Q-learning objective, which decides when to halt and move to a new data sample rather than keep iterating on the same data. This allows much more efficient use of time especially since the average number of supervision steps during training is quite low with ACT (less than 2 steps on the Sudoku-Extreme dataset as per their reported numbers).

However, ACT comes at a cost. This cost is not directly shown in the HRM’s paper, but it is shown in their official code. The Q-learning objective relies on a halting loss and a continue loss. The continue loss requires an extra forward pass through HRM (with all 6 function evaluations). This means that while ACT optimizes time more efficiently per sample, it requires 2 forward passes per optimization step. The exact formulation is shown in Algorithm [2](https://arxiv.org/html/2510.04871v1#S2.F2 "Figure 2 ‣ 2.1 Structure and goal ‣ 2 Background ‣ Less is More: Recursive Reasoning with Tiny Networks").

In the next section, we show that we can bypass the need for two forward passes in ACT.

### 3.3 Hierarchical interpretation based on complex biological arguments

The HRM’s authors justify the two latent variables and two networks operating at different hierarchies based on biological arguments, which are very far from artificial neural networks. They even try to match HRM to actual brain experiments on mice. While interesting, this sort of explanation makes it incredibly hard to parse out why HRM is designed the way it is. Given the lack of ablation table in their paper, the over-reliance on biological arguments and fixed-point theorems (that are not perfectly applicable), it is hard to determine what parts of HRM is helping what and why. Furthermore, it is not clear why they use two latent features rather than other combinations of features.

In the next section, we show that the recursive process can be greatly simplified and understood in a much simpler manner that does not require any biological argument, fixed-point theorem, hierarchical interpretation, nor using two networks. It also explains why 2 is the optimal number of features (z L z_{L} and z H z_{H}).

def latent_recursion(x,y,z,n=6):

4 Tiny Recursion Models
-----------------------

In this section, we present Tiny Recursion Models (TRMs). Contrary to HRM, TRM requires no complex mathematical theorem, hierarchy, nor biological arguments. It generalizes better while requiring only a single tiny network (instead of two medium-size networks) and a single forward pass for the ACT (instead of 2 passes). Our approach is described in Algorithm [3](https://arxiv.org/html/2510.04871v1#S3.F3 "Figure 3 ‣ 3.3 Hierarchical interpretation based on complex biological arguments ‣ 3 Target for improvements in Hierarchical Reasoning Models ‣ Less is More: Recursive Reasoning with Tiny Networks") and illustrated in Figure [1](https://arxiv.org/html/2510.04871v1#S1.F1 "Figure 1 ‣ 1 Introduction ‣ Less is More: Recursive Reasoning with Tiny Networks"). We also provide an ablation in Table [1](https://arxiv.org/html/2510.04871v1#S4.T1 "Table 1 ‣ 4 Tiny Recursion Models ‣ Less is More: Recursive Reasoning with Tiny Networks") on the Sudoku-Extreme dataset (a dataset of difficult Sudokus with only 1K training examples, but 423K test examples). Below, we explain the key components of TRMs.

### 4.1 No fixed-point theorem required

HRM assumes that the recursions converge to a fixed-point for both z L z_{L} and z H z_{H} in order to leverage the 1-step gradient approximation (Bai et al., [2019](https://arxiv.org/html/2510.04871v1#bib.bib3)). This allows the authors to justify only back-propagating through the last two function evaluations (1 f L f_{L} and 1 f H f_{H}). To bypass this theoretical requirement, we define a full recursion process as containing n n evaluations of f L f_{L} and 1 evaluation of f H f_{H}:

z L\displaystyle z_{L}←f L​(z L+z H+x)\displaystyle\leftarrow f_{L}\left(z_{L}+z_{H}+x\right)
…\displaystyle...
z L\displaystyle z_{L}←f L​(z L+z H+x)\displaystyle\leftarrow f_{L}\left(z_{L}+z_{H}+x\right)
z H\displaystyle z_{H}←f H​(z L+z H).\displaystyle\leftarrow f_{H}\left(z_{L}+z_{H}\right).

Then, we simply back-propagate through the full recursion process.

Through deep supervision, the models learns to take any (z L,z H)(z_{L},z_{H}) and improve it through a full recursion process, hopefully making z H z_{H} closer to the solution. This means that by the design of the deep supervision goal, running a few full recursion processes (even without gradients) is expected to bring us closer to the solution. We propose to run T−1 T-1 recursion processes without gradient to improve (z L,z H)(z_{L},z_{H}) before running one recursion process with backpropagation.

Thus, instead of using the 1-step gradient approximation, we apply a full recursion process containing n n evaluations of f L f_{L} and 1 evaluation of f H f_{H}. This removes entirely the need to assume that a fixed-point is reached and the use of the IFT theorem with 1-step gradient approximation. Yet, we can still leverage multiple backpropagation-free recursion processes to improve (z L,z H)(z_{L},z_{H}). With this approach, we obtain a massive boost in generalization on Sudoku-Extreme (improving TRM from 56.5% to 87.4%; see Table 1).

### 4.2 Simpler reinterpretation of z H z_{H} and z L z_{L}

HRM is interpreted as doing hierarchical reasoning over two latent features of different hierarchies due to arguments from biology. However, one might wonder why use two latent features instead of 1, 3, or more? And do we really need to justify these so-called ”hierarchical” features based on biology to make sense of them? We propose a simple non-biological explanation, which is more natural, and directly answers the question of why there are 2 features.

The fact of the matter is: z H z_{H} is simply the current (embedded) solution. The embedding is reversed by applying the output head and rounding to the nearest token using the argmax operation. On the other hand, z L z_{L} is a latent feature that does not directly correspond to a solution, but it can be transformed into a solution by applying z H←f H​(x,z L,z H)z_{H}\leftarrow f_{H}(x,z_{L},z_{H}). We show an example on Sudoku-Extreme in Figure [6](https://arxiv.org/html/2510.04871v1#Ax4.F6 "Figure 6 ‣ Example on Sudoku-Extreme ‣ Less is More: Recursive Reasoning with Tiny Networks") to highlight the fact that z H z_{H} does correspond to the solution, but z L z_{L} does not.

Once this is understood, hierarchy is not needed; there is simply an input x x, a proposed solution y y (previously called z H z_{H}), and a latent reasoning feature z z (previously called z L z_{L}). Given the input question x x, current solution y y, and current latent reasoning z z, the model recursively improves its latent z z. Then, given the current latent z z and the previous solution y y, the model proposes a new solution y y (or stay at the current solution if its already good).

Although this has no direct influence on the algorithm, this re-interpretation is much simpler and natural. It answers the question about why two features: remembering in context the question x x, previous reasoning z z, and previous answer y y helps the model iterate on the next reasoning z z and then the next answer y y. If we were not passing the previous reasoning z z, the model would forget how it got to the previous solution y y (since z z acts similarly as a chain-of-thought). If we were not passing the previous solution y y, then the model would forget what solution it had and would be forced to store the solution y y within z z instead of using it for latent reasoning. Thus, we need both y y and z z separately, and there is no apparent reason why one would need to split z z into multiple features.

While this is intuitive, we wanted to verify whether using more or less features could be helpful. Results are shown in Table [2](https://arxiv.org/html/2510.04871v1#S4.T2 "Table 2 ‣ 4.2 Simpler reinterpretation of 𝑧_𝐻 and 𝑧_𝐿 ‣ 4 Tiny Recursion Models ‣ Less is More: Recursive Reasoning with Tiny Networks").

More features (>2>2): We tested splitting z z into different features by treating each of the n n recursions as producing a different z i z_{i} for i=1,…,n i=1,...,n. Then, each z i z_{i} is carried across supervision steps. The approach is described in Algorithm [5](https://arxiv.org/html/2510.04871v1#Ax3.F5 "Figure 5 ‣ Algorithms with different number of latent features ‣ Less is More: Recursive Reasoning with Tiny Networks"). In doing so, we found performance to drop. This is expected because, as discussed, there is no apparent need for splitting z z into multiple parts. It does not have to be hierarchical.

Single feature: Similarly, we tested the idea of taking a single feature by only carrying z H z_{H} across supervision steps. The approach is described in Algorithm [4](https://arxiv.org/html/2510.04871v1#Ax3.F4 "Figure 4 ‣ Algorithms with different number of latent features ‣ Less is More: Recursive Reasoning with Tiny Networks"). In doing so, we found performance to drop. This is expected because, as discussed, it forces the model to store the solution y y within z z.

Thus, we explored using more or less latent variables on Sudoku-Extreme, but found that having only y y and z z lead to better test accuracy in addition to being the simplest more natural approach.

### 4.3 Single network

HRM uses two networks, one applied frequently as a _low-level_ module f H f_{H} and one applied rarely as an _high-level_ module (f H f_{H}). This requires twice the number of parameters compared to regular supervised learning with a single network.

As mentioned previously, while f L f_{L} iterates on the latent reasoning feature z z (z L z_{L} in HRM), the goal of f H f_{H} is to update the solution y y (z H z_{H} in HRM) given the latent reasoning and current solution. Importantly, since z←f L​(x+y+z)z\leftarrow f_{L}(x+y+z) contains x x but y←f H​(y+z)y\leftarrow f_{H}(y+z) does not contains x x, the task to achieve (iterating on z z versus using z z to update y y) is directly specified by the inclusion or lack of x x in the inputs. Thus, we considered the possibility that both networks could be replaced by a single network doing both tasks. In doing so, we obtain better generalization on Sudoku-Extreme (improving TRM from 82.4% to 87.4%; see Table 1) while reducing the number of parameters by half. It turns out that a single network is enough.

### 4.4 Less is more

We attempted to increase capacity by increasing the number of layers in order to scale the model. Surprisingly, we found that adding layers decreased generalization due to overfitting. In doing the opposite, decreasing the number of layers while scaling the number of recursions (n n) proportionally (to keep the amount of compute and emulated depth approximately the same), we found that using 2 layers (instead of 4 layers) maximized generalization. In doing so, we obtain better generalization on Sudoku-Extreme (improving TRM from 79.5% to 87.4%; see Table 1) while reducing the number of parameters by half (again).

It is quite surprising that smaller networks are better, but 2 layers seems to be the optimal choice. Bai & Melas-Kyriazi ([2024](https://arxiv.org/html/2510.04871v1#bib.bib4)) also observed optimal performance for 2-layers in the context of deep equilibrium diffusion models; however, they had similar performance to the bigger networks, while we instead observe better performance with 2 layers. This may appear unusual, as with modern neural networks, generalization tends to directly correlate with model sizes. However, when data is too scarce and model size is large, there can be an overfitting penalty (Kaplan et al., [2020](https://arxiv.org/html/2510.04871v1#bib.bib15)). This is likely an indication that there is too little data. Thus, using tiny networks with deep recursion and deep supervision appears to allow us to bypass a lot of the overfitting.

### 4.5 attention-free architecture for tasks with small fixed context length

Self-attention is particularly good for long-context lengths when L≫D L\gg D since it only requires a matrix of [D,3​D][D,3D] parameters, even though it can account for the whole sequence. However, when focusing on tasks where L≤D L\leq D, a linear layer is cheap, requiring only a matrix of [L,L][L,L] parameters. Taking inspiration from the MLP-Mixer (Tolstikhin et al., [2021](https://arxiv.org/html/2510.04871v1#bib.bib32)), we can replace the self-attention layer with a multilayer perceptron (MLP) applied on the sequence length. Using an MLP instead of self-attention, we obtain better generalization on Sudoku-Extreme (improving from 74.7% to 87.4%; see Table [1](https://arxiv.org/html/2510.04871v1#S4.T1 "Table 1 ‣ 4 Tiny Recursion Models ‣ Less is More: Recursive Reasoning with Tiny Networks")). This worked well on Sudoku 9x9 grids, given the small and fixed context length; however, we found this architecture to be suboptimal for tasks with large context length, such as Maze-Hard and ARC-AGI (both using 30x30 grids). We show results with and without self-attention for all experiments.

### 4.6 No additional forward pass needed with ACT

As previously mentioned, the implementation of ACT in HRM through Q-learning requires two forward passes, which slows down training. We propose a simple solution, which is to get rid of the continue loss (from the Q-learning) and only learn a halting probability through a Binary-Cross-Entropy loss of having reached the correct solution. By removing the continue loss, we remove the need for the expensive second forward pass, while still being able to determine when to halt with relatively good accuracy. We found no significant difference in generalization from this change (going from 86.1% to 87.4%; see Table [1](https://arxiv.org/html/2510.04871v1#S4.T1 "Table 1 ‣ 4 Tiny Recursion Models ‣ Less is More: Recursive Reasoning with Tiny Networks")).

### 4.7 Exponential Moving Average (EMA)

On small data (such as Sudoku-Extreme and Maze-Hard), HRM tends to overfit quickly and then diverge. To reduce this problem and improves stability, we integrate Exponential Moving Average (EMA) of the weights, a common technique in GANs and diffusion models to improve stability (Brock et al., [2018](https://arxiv.org/html/2510.04871v1#bib.bib5); Song & Ermon, [2020](https://arxiv.org/html/2510.04871v1#bib.bib30)). We find that it prevents sharp collapse and leads to higher generalization (going from 79.9% to 87.4%; see Table [1](https://arxiv.org/html/2510.04871v1#S4.T1 "Table 1 ‣ 4 Tiny Recursion Models ‣ Less is More: Recursive Reasoning with Tiny Networks")).

### 4.8 Optimal the number of recursions

We experimented with different number of recursions by varying T T and n n and found that T=3,n=3 T=3,n=3 (equivalent to 48 recursions) in HRM and T=3,n=6 T=3,n=6 in TRM (equivalent to 42 recursions) to lead to optimal generalization on Sudoku-Extreme. More recursions could be helpful for harder problems (we have not tested it, given our limited resources); however, increasing either T T or n n incurs massive slowdowns. We show results at different n n and T T for HRM and TRM in Table [3](https://arxiv.org/html/2510.04871v1#S4.T3 "Table 3 ‣ 4.8 Optimal the number of recursions ‣ 4 Tiny Recursion Models ‣ Less is More: Recursive Reasoning with Tiny Networks"). Note that TRM requires backpropagation through a full recursion process, thus increasing n n too much leads to Out Of Memory (OOM) errors. However, this memory cost is well worth its price in gold.

5 Results
---------

Following Wang et al. ([2025](https://arxiv.org/html/2510.04871v1#bib.bib34)), we test our approach on the following datasets: Sudoku-Extreme (Wang et al., [2025](https://arxiv.org/html/2510.04871v1#bib.bib34)), Maze-Hard (Wang et al., [2025](https://arxiv.org/html/2510.04871v1#bib.bib34)), ARC-AGI-1 (Chollet, [2019](https://arxiv.org/html/2510.04871v1#bib.bib6)) and, ARC-AGI-2 (Chollet et al., [2025](https://arxiv.org/html/2510.04871v1#bib.bib7)). Results are presented in Tables [4](https://arxiv.org/html/2510.04871v1#S5.T4 "Table 4 ‣ 5 Results ‣ Less is More: Recursive Reasoning with Tiny Networks") and [5](https://arxiv.org/html/2510.04871v1#S5.T5 "Table 5 ‣ 5 Results ‣ Less is More: Recursive Reasoning with Tiny Networks"). Hyperparameters are detailed in Section [Hyper-parameters and setup](https://arxiv.org/html/2510.04871v1#Ax1 "Hyper-parameters and setup ‣ Less is More: Recursive Reasoning with Tiny Networks"). Datasets are discussed below.

Sudoku-Extreme consists of extremely difficult Sudoku puzzles (Dillion, [2025](https://arxiv.org/html/2510.04871v1#bib.bib9); Palm et al., [2018](https://arxiv.org/html/2510.04871v1#bib.bib23); Park, [2018](https://arxiv.org/html/2510.04871v1#bib.bib24)) (9x9 grid), for which only 1K training samples are used to test small-sample learning. Testing is done on 423K samples. Maze-Hard consists of 30x30 mazes generated by the procedure by Lehnert et al. ([2024](https://arxiv.org/html/2510.04871v1#bib.bib19)) whose shortest path is of length above 110; both the training set and test set include 1000 mazes.

ARC-AGI-1 and ARC-AGI-2 are geometric puzzles involving monetary prizes. Each puzzle is designed to be easy for a human, yet hard for current AI models. Each puzzle task consists of 2-3 input–output demonstration pairs and 1-2 test inputs to be solved. The final score is computed as the accuracy over all test inputs from two attempts to produce the correct output grid. The maximum grid size is 30x30. ARC-AGI-1 contains 800 tasks, while ARC-AGI-2 contains 1120 tasks. We also augment our data with the 160 tasks from the closely related ConceptARC dataset (Moskvichev et al., [2023](https://arxiv.org/html/2510.04871v1#bib.bib22)). We provide results on the public evaluation set for both ARC-AGI-1 and ARC-AGI-2.

While these datasets are small, heavy data-augmentation is used in order to improve generalization. Sudoku-Extreme uses 1000 shuffling (done without breaking the Sudoku rules) augmentations per data example. Maze-Hard uses 8 dihedral transformations per data example. ARC-AGI uses 1000 data augmentations (color permutation, dihedral-group, and translations transformations) per data example. The dihedral-group transformations consist of random 90-degree rotations, horizontal/vertical flips, and reflections.

From the results, we see that TRM without self-attention obtains the best generalization on Sudoku-Extreme (87.4% test accuracy). Meanwhile, TRM with self-attention generalizes better on the other tasks (probably due to inductive biases and the overcapacity of the MLP on large 30x30 grids). TRM with self-attention obtains 85.3% accuracy on Maze-Hard, 44.6% accuracy on ARC-AGI-1, and 7.8% accuracy on ARC-AGI-2 with 7M parameters. This is significantly higher than the 74.5%, 40.3%, and 5.0% obtained by HRM using 4 times the number of parameters (27M).

6 Conclusion
------------

We propose Tiny Recursion Models (TRM), a simple recursive reasoning approach that achieves strong generalization on hard tasks using a single tiny network recursing on its latent reasoning feature and progressively improving its final answer. Contrary to the Hierarchical Reasoning Model (HRM), TRM requires no fixed-point theorem, no complex biological justifications, and no hierarchy. It significantly reduces the number of parameters by halving the number of layers and replacing the two networks with a single tiny network. It also simplifies the halting process, removing the need for the extra forward pass. Overall, TRM is much simpler than HRM, while achieving better generalization.

While our approach led to better generalization on 4 benchmarks, every choice made is not guaranteed to be optimal on every dataset. For example, we found that replacing the self-attention with an MLP worked extremely well on Sudoku-Extreme (improving test accuracy by 10%), but poorly on other datasets. Different problem settings may require different architectures or number of parameters. Scaling laws are needed to parametrize these networks optimally. Although we simplified and improved on deep recursion, the question of why recursion helps so much compared to using a larger and deeper network remains to be explained; we suspect it has to do with overfitting, but we have no theory to back this explaination. Not all our ideas made the cut; we briefly discuss some of the failed ideas that we tried but did not work in Section [Ideas that failed](https://arxiv.org/html/2510.04871v1#Ax2 "Ideas that failed ‣ Less is More: Recursive Reasoning with Tiny Networks"). Currently, recursive reasoning models such as HRM and TRM are supervised learning methods rather than generative models. This means that given an input question, they can only provide a single deterministic answer. In many settings, multiple answers exist for a question. Thus, it would be interesting to extend TRM to generative tasks.

Ideas that failed
-----------------

In this section, we quickly mention a few ideas that did not work to prevent others from making the same mistake.

We tried replacing the SwiGLU MLPs by SwiGLU Mixture-of-Experts (MoEs) (Shazeer et al., [2017](https://arxiv.org/html/2510.04871v1#bib.bib28); Fedus et al., [2022](https://arxiv.org/html/2510.04871v1#bib.bib11)), but we found generalization to decrease massively. MoEs clearly add too much unnecessary capacity, just like increasing the number of layers does.

Instead of back-propagating through the whole n+1 n+1 recursions, we tried a compromise between HRM 1-step gradient approximation, which back-propagates through the last 2 recursions. We did so by decoupling n n from the _number of last recursions_ k k that we back-propagate through. For example, while n=6 n=6 requires 7 steps with gradients in TRM, we can use gradients for only the k=4 k=4 last steps. However, we found that this did not help generalization in any way, and it made the approach more complicated. Back-propagating through the whole n+1 n+1 recursions makes the most sense and works best.

We tried removing ACT with the option of stopping when the solution is reached, but we found that generalization dropped significantly. This can probably be attributed to the fact that the model is spending too much time on the same data samples rather than focusing on learning on a wide range of data samples.

We tried weight tying the input embedding and output head, but this was too constraining and led to a massive generalization drop.

We tried using TorchDEQ (Geng & Kolter, [2023](https://arxiv.org/html/2510.04871v1#bib.bib12)) to replace the recursion steps by fixed-point iteration as done by Deep Equilibrium Models (Bai et al., [2019](https://arxiv.org/html/2510.04871v1#bib.bib3)). This would provide a better justification for the 1-step gradient approximation. However, this slowed down training due to the fixed-point iteration and led to worse generalization. This highlights the fact that converging to a fixed-point is not essential.

class TinyRecursiveModel:
    """
    TRM-inspired recursive reasoning in PTX.
    
    Based on: "Less is More: Recursive Reasoning with Tiny Networks" (2025)
    - Single tiny 2-layer network (7M params)
    - Recursive refinement: z ← net(x,y,z), y ← net(y,z)
    - Deep supervision with adaptive halting (ACT without double forward pass)
    """
    
    def __init__(self, hidden_dim=512, n_recursions=6, T_iterations=3):
        self.hidden_dim = hidden_dim
        self.n = n_recursions      # TRM optimal: n=6
        self.T = T_iterations       # TRM optimal: T=3
        
        # Load PTX kernels
        ptx_dir = Path(__file__).parent.parent / "cranium" / "ptx"
        with open(ptx_dir / "gre_recursive_refiner.ptx") as f:
            ptx_code = f.read()
        
        self.module = cp.RawModule(code=ptx_code)
        self.recursive_latent_update = self.module.get_function("recursive_latent_update")
        self.answer_refinement = self.module.get_function("answer_refinement")
        self.compute_halting = self.module.get_function("compute_halting_probability")
        
        # Tiny 2-layer MLP weights (on GPU)
        self.weights = self._init_tiny_network()
    
    def _init_tiny_network(self) -> cp.ndarray:
        """2-layer MLP: 512 → 1024 (SwiGLU) → 512"""
        # Much smaller than transformers: ~7M params total
        w1 = cp.random.randn(512, 1024, dtype=cp.float32) * 0.02
        w2 = cp.random.randn(1024, 512, dtype=cp.float32) * 0.02
        return cp.concatenate([w1.ravel(), w2.ravel()])
    
    def recursive_refine(
        self, 
        question: cp.ndarray,      # (batch, 512) - input embedding
        answer: cp.ndarray,         # (batch, 512) - current answer
        latent: cp.ndarray,         # (batch, 512) - reasoning state
        max_supervision_steps: int = 16,
        training: bool = False,
        ground_truth: Optional[cp.ndarray] = None
    ) -> Tuple[cp.ndarray, cp.ndarray, int]:
        """
        Progressive answer refinement through recursive reasoning.
        
        Returns:
            refined_answer: (batch, 512)
            final_latent: (batch, 512)
            steps_taken: int (for ACT tracking)
        """
        batch_size = question.shape[0]
        
        # Allocate RecursiveState buffer on GPU
        states = cp.zeros(batch_size, dtype=[
            ('question', cp.float32, 512),
            ('latent', cp.float32, 512),
            ('answer', cp.float32, 512),
            ('recursion_depth', cp.uint32),
            ('confidence', cp.float32),
            ('converged', cp.uint32)
        ])
        
        states['question'] = question
        states['answer'] = answer
        states['latent'] = latent
        
        supervision_step = 0
        for sup_step in range(max_supervision_steps):
            # T-1 iterations WITHOUT gradients (fast inference)
            for t in range(self.T - 1):
                self.recursive_latent_update(
                    (batch_size,), (32,),  # grid, block
                    (states.data.ptr, self.weights.data.ptr, 
                     batch_size, self.n, 0)  # with_gradients=0
                )
                self.answer_refinement(
                    (batch_size,), (32,),
                    (states.data.ptr, self.weights.data.ptr, batch_size)
                )
            
            # Final iteration WITH gradients (learning)
            self.recursive_latent_update(
                (batch_size,), (32,),
                (states.data.ptr, self.weights.data.ptr,
                 batch_size, self.n, 1)  # with_gradients=1
            )
            self.answer_refinement(
                (batch_size,), (32,),
                (states.data.ptr, self.weights.data.ptr, batch_size)
            )
            
            # Compute halting probability (ACT without second forward pass!)
            self.compute_halting(
                (batch_size,), (32,),
                (states.data.ptr, self.weights.data.ptr,
                 ground_truth.data.ptr if training else 0,
                 batch_size, 1 if training else 0)
            )
            
            # Check convergence (early stopping)
            if cp.all(states['converged']):
                supervision_step = sup_step + 1
                break
        
        return states['answer'], states['latent'], supervision_step

def launch(x, y, z, max_steps=16, stream=None):
    """
    x,y,z: cp.ndarray (batch, 512) fp32
    returns: (y_refined, z_refined, steps_taken, elapsed_us)
    """
    batch = x.shape[0]
    y_out = cp.empty_like(y)
    z_out = cp.empty_like(z)
    halt  = cp.zeros(batch, dtype=cp.uint32)

    for step in range(max_steps):
        _kernel((batch,), (256,), (x, y, z, y_out, z_out, halt), stream=stream)
        if int(halt.sum()) == batch:
            break
        y, z = y_out, z_out

    stream.synchronize() if stream else cp.cuda.runtime.deviceSynchronize()
    elapsed = cp.cuda.get_elapsed_time() * 1000  # ms → µs
    return y_out, z_out, step+1, elapsed
