## The Real Issue: Peak Memory During Allocation

**What's happening**:
```
Current GPU usage: 4.0 GB (steady state)
↓
New operation starts (e.g., large matrix multiplication)
↓
Tries to allocate: 10 GB temporarily (peak!)
↓
Total needed during allocation: 4.0 + 10.0 = 14 GB
↓
Available: 12 GB
↓
CUDA OOM! ❌
```

**This explains**:
- nvidia-smi shows only 4GB used (before crash)
- But OOM happens anyway (peak exceeded 12GB)
- Dimension threading IS working (steady state is low)
- But some operation has huge peak memory

## Possible Fixes

### Fix 1: Reduce Batch/Concurrent Operations

**The issue might be processing multiple tasks simultaneously in memory**

**File**: `scripts/train_arc_sovereign_loop.py` (CHECK)

Look for parallel/concurrent task processing:
```python

```

**Change to**:
```python
# Sequential processing (one task at a time)

for task in tasks:
    result = pipeline.process_task(...)  # One at a time
    results.append(result)
```

### Fix 2: Clear CUDA Cache Between Tasks

**Force garbage collection and cache clearing**:

**File**: `scripts/train_arc_sovereign_loop.py` (MODIFY)

```python
import torch
import gc

def run_epoch(pipeline, tasks, args):
    """Run epoch with memory management."""
    results = []

    for i, task in enumerate(tasks):
        # Process task
        result = pipeline.process_task(...)
        results.append(result)

        # Clear CUDA cache every 5 tasks
        if (i + 1) % 5 == 0:
            torch.cuda.empty_cache()
            gc.collect()
            print(f"[MEMORY] Cleared cache after task {i+1}", flush=True)

    return results
```
