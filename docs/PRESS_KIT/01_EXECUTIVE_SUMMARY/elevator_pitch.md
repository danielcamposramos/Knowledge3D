# Elevator Pitch Set

## 30-second version (about 50 words)
PM-KR is a W3C effort to store knowledge once as procedural source and reuse it everywhere through references. Our K3D implementation shows measurable compression, deterministic traces, and a lower-compute path for AI. The climate model projects up to 12 Gt CO2 cumulative savings over 10 years under large-scale adoption scenarios.

## 1-minute version (about 150 words)
We are building PM-KR, a W3C Community Group initiative that treats knowledge like executable infrastructure instead of duplicated documents. In current systems, the same concept is copied into many formats for rendering, search, accessibility, and AI training. PM-KR defines one canonical procedural representation, then references it across layers. That gives humans and AI the same source of truth, with auditable traces and deterministic reconstruction.

Knowledge3D is our reference implementation. It combines procedural memory, symlink-style composition, and sovereign runtime constraints for the hot path. We are grounding this work in public specifications, validation matrices, and measurable compression evidence. We are also framing sustainability directly: our carbon blueprint models a 10-year cumulative 12 Gt CO2 savings scenario if procedural approaches displace large portions of repetitive AI compute. This is not a product slogan; it is a standards and engineering track with reproducible artifacts.
It is designed to be reviewed, challenged, and improved in the open.

## 5-minute version (about 750 words)
PM-KR starts from a practical systems problem: knowledge duplication. The same symbol, rule, or definition is repeatedly copied across storage layers, app formats, accessibility outputs, embeddings, and model-centric pipelines. Each copy drifts over time. Each copy adds compute and maintenance burden. And every copy increases audit complexity when organizations need to answer a basic question: what is the canonical version?

Our response is procedural memory as a specification target. Instead of storing many static copies, we store one canonical procedural source and expose it through references. Think of it as symlink semantics for knowledge. Humans can inspect it. AI systems can execute it. Accessibility channels can render from it. But everyone uses the same source, so consistency is not a side-effect, it is an architectural property.

This is the mission of PM-KR at W3C: define a data model, execution semantics, conformance profiles, and interoperability pathways so this approach is not isolated to one codebase. Knowledge3D is our reference implementation, where we test the hard parts in production-like constraints: deterministic reconstruction, boundary-aware governance, and sovereign hot-path execution with no hidden fallbacks.

Why this matters now:
1. AI system cost and energy curves are rising fast.
2. Organizations are struggling with fragmented and duplicated knowledge pipelines.
3. Regulators and enterprises increasingly require traceability and explainability.
4. Cross-border standards work needs shared models that are implementation-neutral but technically testable.

PM-KR is not "replace everything." It is a structured layer that can coexist with RDF/OWL/JSON-LD and existing web standards. Declarative models remain useful for semantic description. PM-KR adds a procedural execution layer so knowledge is not only described, but operationally reusable and auditable.

We are also explicit about governance and sovereignty. Through boundary contracts and policy dials, we separate public, collaborator, regulator, and internal visibility modes. That avoids the false binary of full opacity versus radical transparency. It supports practical deployment in enterprise and public-interest settings where some forces must remain private but all critical decisions must remain auditable.

From a sustainability angle, we are publishing a carbon blueprint that models cumulative impact over 10 years. The headline scenario is 12 Gt CO2 cumulative savings, with annual savings reaching 2.5 Gt by 2035 under broad adoption assumptions. We present this as a scenario model, not a guaranteed baseline. The goal is clear assumptions, transparent methodology, and ongoing refinement as deployment evidence grows.

The international dimension is central. This work is co-chaired by Daniel Campos Ramos in Brazil and Milton Ponson in the Netherlands, within a W3C context. It creates a concrete MERCOSUR-EU collaboration path in frontier technologies: procedural AI technology, sustainable compute, and spatial knowledge systems. We are pairing hardware and systems engineering with mathematical and environmental framing, so the resulting stack is both executable and accountable.

For media, the simplest summary is this: PM-KR and K3D propose a Community Group-first path to reduce knowledge duplication, improve traceability, and lower AI compute waste. For developers, the summary is: canonical procedural nodes plus references, deterministic runtime behavior, and conformance-driven interoperability. For policymakers, the summary is: auditable systems with explicit boundary governance and measurable sustainability targets.

If you want to evaluate this seriously, do not start with slogans. Start with the artifacts: normative model, evidence matrix, conformance profiles, reference implementation, and benchmark reports. That is where this work should be judged.

Concrete use cases make this easier to evaluate. In display systems, canonical procedural representations can reduce duplicated rendering bundles across language and accessibility variants. In enterprise knowledge systems, one policy source can be reused in legal, finance, onboarding, and assistant workflows without maintaining conflicting copies. In specification work, PM-KR can contribute executable continuity while preserving compatibility discussions with declarative ecosystems.

The work is also intentionally international. The co-chair collaboration between Brazil and the Netherlands is framed as a MERCOSUR-EU frontier technology track with public documentation and standards artifacts. This matters because the project is not only proposing architecture, it is also modeling how open technical governance can be built across regions with different constraints, priorities, and institutional contexts.

For communication and onboarding, we are also packaging this work for reproducible media workflows. The press kit is structured for NotebookLM and graphics generation pipelines so that public communication stays aligned with source documents instead of drifting into generic claims. That is a small but important governance detail: if visuals, slides, and interview materials are generated from the same grounded corpus, the risk of narrative mismatch is lower. This keeps outreach and standards work synchronized.
