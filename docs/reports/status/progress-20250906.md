Reproduction (GPU‑First)
- Conda env: `conda env create -f envs/k3d-rapids.yml && conda activate k3d-rapids && pip install -e .`
- Torch CUDA: `python -m pip install --index-url https://download.pytorch.org/whl/cu118 torch torchvision torchaudio`
- Build GLB: `env K3D_ACCEL=gpu K3D_FAISS_DEVICE=gpu K3D_ACCEL_LOG=1 python -m k3dgen ../Knowledge3D.local/datasets/ai_compendium_240k_vectors.csv --gltf ../Knowledge3D.local/datasets/ai_compendium.240k.umap.ivfpq.glb --k 10 --reducer umap --ann ivfpq --emb-precision f16`
- Train HF: `env CUDA_VISIBLE_DEVICES=0 python -m knowledge3d.models.intent_hf train --fp16 --epochs 2 --synth-per-label 80 --batch-size 16 --langs en,pt,es,fr,de,it,zh,ja`

Assessments (Plain Language)
- HF Eval Accuracy: “How often did the model pick the right action label on a held‑out set of commands?” High values show strong understanding of phrasing across languages; we still verify on real logs to avoid template overfitting.
- Routing Scoreboard: “How reliably and efficiently do we reach a labeled point?” Higher success and fewer hops signal better neighborhood structure and door placement.
- Accel Logs: “Which engine did we use?” Messages like “UMAP via RAPIDS cuML (GPU)” confirm GPU paths; otherwise we improve env until they appear.

K3D vs GPT‑OSS Memory (Non‑Expert)
- GPT‑OSS keeps most knowledge inside its brain (weights). K3D keeps knowledge in space (3D house) and trains a smaller brain to navigate it.
- Benefits: Easier updates (drop new rooms), transparent paths (“we went from A→B→C”), and multi‑agent exploration to grow data.
