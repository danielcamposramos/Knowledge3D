## What We Identified as Missing

### Milton Ponson (Co-Chair): Spatiotemporal + Paradigm Gaps

**Key focus areas:**
1. **3D spatiotemporal modeling** - Current AI lacks spatial reasoning (GenAI/LLMs are fundamentally 1D text sequences)
2. **Monolithic vs application-specific AI** - One-size-fits-all models vs domain-optimized systems
3. **Knowledge representation limitations** - LLMs memorize patterns, don't represent knowledge procedurally
4. **Memory, storage, application environment** - Implications of where AI runs (cloud vs edge, VRAM vs disk)

**Core insight:** AI needs to model reality *spatially* and *temporally*, not just textually. Current GenAI treats knowledge as token sequences; PM-KR treats it as compositional procedures in 3D space.

**Background:**
- Strong foundation in AI, computer science, and mathematics
- Focus on actionable systems (not just theory)
- Affiliations: PM-KR CG (co-chair), other W3C groups (details forthcoming)
- Key work: https://github.com/rwi-ciamsd (spatiotemporal modeling)

### Daniel Campos Ramos (Co-Chair): Hyper-Modularity + Dual-Client

**Key focus areas:**
1. **Knowledge duplication crisis** - Same knowledge (characters, symbols, concepts) duplicated across systems
2. **Dual-client paradigm** - Humans and AI should consume the SAME canonical knowledge source
3. **Hyper-modular architecture** - Atomic knowledge units compose into complex structures (no duplication)
4. **Procedural foundation** - Knowledge as executable procedures (like TrueType fonts), not static data

**Core insight:** Knowledge should be stored ONCE (procedurally) and referenced via composition. Current systems duplicate knowledge across embeddings, databases, training data — PM-KR eliminates duplication.

## Our Game Plan

### Objectives (What We're Solving)

1. **Knowledge duplication** → One canonical procedural source
2. **AI spatial reasoning gaps** → 3D compositional knowledge structures
3. **LLM memorization limitations** → Executable procedural programs
4. **Accessibility barriers** → Multi-modal rendering from one source
5. **Sustainability (carbon)** → 50-90% compression via deduplication

### Goals (What We're Building)

**Year 1 (2026):**
- PM-KR Core Specification v1.0 (Q4 2026)
- Reference implementation (Knowledge3D - Python/CUDA)
- Empirical validation (compression benchmarks, accuracy tests)
- Use case documentation (education, accessibility, games, science)

**Year 2 (2027):**

## What Makes PM-KR Different from GenAI/LLMs

**Current GenAI/LLMs:**
- Memorize patterns (statistical correlations)
- 1D text sequences (no spatial reasoning)
- Monolithic models (one size fits all)
- Duplicated training data (Wikipedia × N companies)
- Black box (can't inspect knowledge)

**PM-KR paradigm:**
- Represent knowledge procedurally (executable programs)
- 3D compositional space (spatial + temporal reasoning)
- Hyper-modular (domain-specific composition)
- Canonical sources (one knowledge base, N consumers)
- Inspectable (human-readable + machine-executable)

**Result:** PM-KR complements LLMs (provides structured knowledge layer they currently lack).
